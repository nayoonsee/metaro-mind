# 종합사주 리포트 제작 프로그램 (로컬 무료 MVP)

판매자가 자기 브랜드로 고객 리포트를 만드는 로컬 프로그램이에요. 유료 AI를 쓰지 않아요.
**판매 준비 완료 상태가 아니에요.** 문단 라이브러리의 전문가 검수와 실제 이메일 연결이 남아 있어요(아래 "남은 일").

## 실행

필요한 것: Node.js 20 이상. PDF 버튼을 쓰려면 Chromium(Playwright)이 필요하고, PDF 자동 검사에는 `pdftotext`(poppler-utils)가 필요해요.

```bash
# 저장소 루트에서
npm install                        # 계산 엔진 의존성(lunar-javascript, manseryeok)
npm install --prefix report-app    # PDF용 Playwright (선택)
npx --prefix report-app playwright install chromium   # Chromium 내려받기 (선택, 무료)
npm start --prefix report-app      # → http://127.0.0.1:4310
```

- Playwright가 없어도 입력·생성·수정·저장·미리보기는 동작해요. 이때 PDF는 미리보기 화면에서 브라우저 인쇄(PDF로 저장)로 만들어요.
- 이미 다른 위치에 Playwright가 설치돼 있으면 `NODE_PATH=<그 node_modules 경로>`, Chromium 경로는 `CHROMIUM_PATH=<실행 파일>`로 지정할 수 있어요.
- `pdftotext`가 없으면 PDF는 만들어지지만 페이지 나눔 자동 검사를 건너뛰고, 화면에 "직접 확인 필요"로 표시해요.

## 사용 흐름

1. **입력**: 브랜드(이름·대표 색·표지), 고객 이름, 생년월일(양력/음력·윤달), 출생 시간 또는 "시간 모름". 선택으로 현재 고민·상황·선택지(최대 3개)·기간을 입력해요.
   - 지원 범위: 1900~2099년, 한국 출생(한국 표준시, 당시 서머타임 자동 보정).
   - 자동 집중 풀이가 되는 고민: 일·진로 선택, 돈 관리. 그 밖의 질문은 근거 없이 풀지 않고, 7장에 **직접 작성 칸**으로 남겨요.
2. **내용 확인·수정**: 장마다 문장을 직접 고칠 수 있어요. 고친 문장은 표시되고, 다시 생성해도 보존돼요. 새 결과에 같은 자리가 없는 편집본은 "보존된 편집본"으로 모아 둬요. 검토 항목(시간 모름, 밤 11시대 출생, 직접 작성 필요 등)은 고객용 리포트에 나오지 않아요.
3. **미리보기·PDF**: 같은 렌더러로 미리보기와 PDF를 만들어요. PDF는 페이지 나눔 자동 검사를 통과해야만 받을 수 있어요. 브랜드명을 비워 두면 "시험본" 표시가 붙어요.
4. **전달**: 검토 완료 체크 → 받는 사람·제목·본문 확인 → 발송 대기. **현재 전송기는 테스트용이에요.** 실제로 메일을 보내지 않고, 로컬 `outbox-test/`에 대기 기록(받는 사람, 제목, 첨부 크기)만 남겨요. 화면에도 "실제 발송 아님"으로 표시돼요.

저장: 프로젝트는 이 브라우저(localStorage)에 저장돼요. 다른 기기로 옮기거나 백업하려면 "JSON 백업"을 쓰세요.

## 리포트 구성 (규칙 기반 생성)

읽는 법 · 1 기본 성향 · 2 강점과 반복되는 어려움 · 3 일과 적성 · 4 돈 관리 · 5 연애와 관계 · 6 가족과 대인관계 · 7 현재 고민 · 8 선택과 실천 · 부록 계산 기준

- 장마다 다른 계산 요소를 써요: 일간·월지(1장), 천간에 드러난 십성 전부(2장), 천간 조합(3장), 재성의 자리(4장), 일지 속 중심 글자(5장), 년주(6장).
- **넣지 않은 것**: 올해 흐름(문장 연결 규칙 미검증), 대운(시작 나이·순서 미검증), 특정 시기 예측, 궁합·결혼 시기·재산 규모·건강.
- 밤 11시대 출생: 현재 구현은 일주는 그날, 시주 천간은 다음날 일간 기준이에요. 상품 기준은 미확정이라 검토 항목으로 표시해요.

## 개인정보

- 서버는 `127.0.0.1`에서만 열리고, 입력 내용을 외부로 보내거나 로그에 남기지 않아요(오류 시 상태 코드와 짧은 메시지만).
- 미리보기·PDF에 쓰는 글꼴은 Google Fonts에서 받아요. 글꼴 요청에는 고객 정보가 들어가지 않아요. 완전한 오프라인 사용에는 글꼴 파일을 함께 넣는 작업이 필요해요.
- API 키나 메일 비밀값은 소스와 화면 어디에도 없어요.

## 테스트

```bash
node report-app/test/e2e.mjs        # 브라우저 종단 간 (Playwright + Chromium + pdftotext 필요)
```

`samples/`에 가상 사례로 실제 생성한 PDF가 있어요(실제 사람 정보 아님).

## 남은 일 (판매 전)

1. **문단 라이브러리 전문가 검수**: `report/chapters/library.mjs`, `library2.mjs`는 Claude 초안이에요.
2. **실제 이메일 연결**: 필요한 설정은 하나예요. 구매자 본인 메일 계정의 발송 수단(예: SMTP 앱 비밀번호, 또는 Gmail API OAuth)을 **서버 환경변수**로 넣고 `lib/mail.mjs`에 실제 전송기를 추가하는 것이에요. 계정별 발송 한도·인증 절차는 연결 전에 확인이 필요하고, 아직 실검증하지 않았어요.
3. 깨끗한 새 환경에서 위 "실행" 절차 재현 확인.
