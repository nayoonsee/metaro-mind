# 제출 묶음 안내 (510afc7 독립 검토 지적 반영)

## 구성
- `samples/pdf/` — e2e가 **화면에서** 사례마다 같은 프로젝트로 "새 프로젝트 → 입력 → 생성 → 고유 편집 → 저장 → 다시 열기 → 검토 → 최종 PDF"를 실행해 받은 실제 PDF 6개. 파일 이름 = `사례id_고객명_고민 앞부분.pdf`. 각 PDF에는 그 사례의 고유 편집 문장(`[사례id 고유 편집]`)만 들어 있고, 다른 사례 문장이 없음을 테스트가 확인해요.
- `samples/blocked/` — 최종본이 될 수 없는 상태의 PDF(검토 전, 브랜드 미설정, 지원 밖 고민의 직접 작성 칸 비어 있음). 매 쪽에 "검토용 · 최종본 아님"이 찍혀요.
- `samples/screens/` — 사례별 편집·전달 화면, 입력 변경 후 전달 차단 화면(stale), 테스트 메일 대기열("실제 발송 아님") 화면.
- `samples/logs/` — e2e 54개, 리포트 생성 71개, 기존 회귀(브랜드 41 · 장 생성 49 · 비용·개인정보 17 · KST 86 · 점찍 엔진 교차 16) 실행 로그.
- 소스 ZIP — 저장소 루트에서 `git archive`로 만든 report-app·report·api·scripts·vendor·package 파일.

## 2차 보완 (ab756c4 이후 독립 검수 지적 3건)
1. **모든 비동기 응답의 프로젝트 소유권**: 미리보기·PDF·검토·발송 대기도 요청 당시 스냅샷(프로젝트 id, 전환 세대, 내용 revision, 고객·브랜드 이름)을 기억해요. 다른 프로젝트로 바뀐 뒤 도착한 응답은 현재 프로젝트를 바꾸지 않아요. PDF는 받지 않고, 발송 대기 기록은 요청한 프로젝트의 저장본에만 남아요(실제 발송 아님). 같은 프로젝트에서 내용이 바뀐 뒤 도착한 PDF·미리보기·검토 응답은 버려요. 검토 응답 전에 체크를 풀면 검토 완료가 기록되지 않아요. PDF 파일 이름은 요청 당시 스냅샷을 써요.
2. **저장 실패 시 전환 중단·같은 프로젝트 다시 열기**: 자동 저장에 실패하면(용량 초과 등) 새 프로젝트·열기·불러오기를 멈추고 편집 내용을 화면에 그대로 둬요. 이때도 JSON 백업은 받을 수 있어요. 지금 열린 프로젝트를 목록에서 다시 고르면 저장된 오래된 사본으로 덮어쓰지 않아요. 다른 프로젝트는 현재 프로젝트를 저장한 다음에 읽어요.
3. **가져오기 중첩 구조 검증**: generated.report의 장·질문·문단·검토 항목, mail.queue, history 항목까지 형식을 검사해요. 하나라도 틀리면 적용하지 않고 기존 프로젝트를 그대로 둬요. 서버는 가져온 생성 문장을 쓰지 않고 입력으로 다시 생성해요.

이 테스트 환경의 headless Chromium은 한글 다운로드 파일명을 `download`로 바꿔 보고해요. 그래서 파일명 확인은 앱이 지정한 `download` 속성을 기록하는 방식으로 했어요. 실제 브라우저에서 한글 파일명이 저장되는지는 직접 확인이 필요해요.

## 이전 `case-c-from-ui-edited.pdf` 혼동 설명
이전 e2e는 한 프로젝트(가상 사례 A)를 이어서 쓰면서 고민만 돈 관리로 바꾼 뒤 PDF를 받았고, 그 파일에 `case-c` 이름을 붙였어요. 실제 내용은 **A 고객 + 돈 고민**이었고 C 고객 프로젝트가 아니었어요. 이번에는 사례마다 새 프로젝트를 만들고, 파일 이름에 사례 id·고객명·고민을 함께 넣어 혼동이 생기지 않게 했어요. (A와 C는 같은 생년월일이라 1~6장 기본 해석이 같고 7장만 달라요. 의도된 것이에요.)

## 완료
- 결과-입력 묶기(fingerprint), stale 표시·미검토 처리, 서버의 stale PDF·발송 거절(409)
- 늦은 응답·중복 클릭·프로젝트 전환 시 응답 미적용
- JSON 전체 형식 검사, 렌더러 전체 이스케이프, 미리보기 sandbox, Host/Origin/Content-Type 검사
- 미저장 변경 자동 보관(새 프로젝트·열기·불러오기·창 닫기 경고)
- 최종본 조건(브랜드+검토 해시+직접 작성+입력 일치), 미완성 결과 전달 차단, 테스트 메일 "실제 발송 아님" 유지
- 3~7장 보강(핵심 장 1,000~1,900자, 질문 3개 이상, 의미·장면·주의·활용), 천간만 본 조합 문장 수정, 가족 장 조건부 표현
