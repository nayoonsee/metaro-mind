# 시제품 제출 — 쉬운 제작 흐름 · 브랜드 프로필 · 디자인 5종 · 내용 개선

## 무엇이 바뀌었나
1. **제작 흐름**: 정보 입력 → 디자인 → 리포트 만들기 → 확인·PDF의 네 단계로 바꿨어요.
   - 정보 입력: 이름·양력/음력·생년월일·시간 모름과 핵심 질문만 기본으로 보여요. 상세 고민(상황·선택지·기간)과 계산 범위 설명은 접어 두었어요.
   - 생년월일은 한 칸에 `1990-05-17`이나 `19900517`로 입력할 수 있어요.
   - "내 작업" 메뉴에 저장·JSON 백업·불러오기·저장한 프로젝트 열기를 모았고, 화면을 다시 열면 마지막 작업을 이어서 하라는 안내가 떠요.
   - 편집기에는 장 이동 목록과 옆 미리보기가 있어요. 검토 확인과 부족 항목 차단은 PDF 바로 전 단계에 남겼어요.
   - 메일 칸은 접힌 "이메일로 보내기 — 연결 준비 중"으로 옮겼고, 이미 적어 둔 메일 내용은 그대로 남아요.
2. **브랜드 프로필**:
   - 브랜드명, 로고(PNG·JPEG·WEBP, 다시 그려 저장, SVG 거절), 인사말, 마지막 안내문을 한 번 저장하면 새 고객에 자동으로 채워져요.
   - 이미 있는 고객 프로젝트는 몰래 바뀌지 않아요. "이 고객에 적용"을 눌렀을 때만 바뀌어요.
   - 프로필은 브라우저에만 저장된다고 화면에 밝혔고, 따로 백업·불러오기를 할 수 있어요.
3. **디자인 5종**: 깔끔한 기본형(흰 바탕·무장식), 신비로운 밤, 따뜻한 종이, 차분한 서재, 부드러운 자연.
   - 표지뿐 아니라 제목 계층·본문 카드·명식표·장 시작 모양이 디자인마다 달라요.
   - 이전 `mystic` ID는 "신비로운 밤"으로 그대로 쓰고, `bright`는 이전 표지 그대로 출력돼요.
   - 색은 이름 붙은 팔레트와 색 선택기로 고르고, 색상 코드는 고급 설정에 있어요.
   - 글꼴 카드는 실제 한글 문장으로 보여 줘요. 배포본에 넣은 굵기만 쓰고(OFL), 한자는 같이 넣은 Noto Sans KR로 표시해요.
   - 디자인 카드 그림은 실제 렌더러로 만든 표지와 본문 화면이에요.
4. **생성 오류 수정**:
   - 일 선택지를 재직 유지·재직 중 준비·이직·퇴사 후 구직·프리랜서 독립·창업 여섯 가지로 나눠요. 애매하면 중립 점검만 넣어요.
   - "다니면서 이직 준비"는 더 이상 창업으로 분류되지 않고, "첫 수입/의뢰·고객" 문구도 나오지 않아요.
   - "을(를)" 같은 조사 표식을 없앴어요.
   - 대표 PDF에는 시험용 문구가 없어요. 시험용 고유 편집 문장은 시험 파일에만 남겼어요.
5. **내용 개선**: 대표 사례 A를 기준으로 고쳤어요.
   - 3장(일)은 역할(월간), 권한·규칙(관성 위치), 혼자/함께(비겁 위치), 오래 버틸 환경(월지 관계)을 다뤄요.
   - 4장(돈)은 대가를 받는 방식(식상 위치), 돈을 대하는 감각(재성 위치), 새기 쉬운 지점(비겁 위치)을 다뤄요.
   - 7장(고민)은 선택지마다 구조 차이(사주 해석 아님)를 정리하고, 앞 장의 계산 요소를 근거로 한 확인 사항과 입력 사실에 따른 조건부 판단을 붙여요. 예: "회사 밖 작업이 있다면 지난 3개월 실제 수입·문의가 첫 기준".
   - 맨 앞에 개인별 핵심 3개를, 8장에 "이럴 때 다시 펼칠 곳"(실제 절 제목으로 안내)을 넣었어요.
   - 각 절 끝에 "근거"(다시 계산해 확인할 수 있는 사실)를 달고, 부록에 쓴 계산 요소를 모았어요. 풀이는 "전통적으로 ~로 봐요"로 구분했어요.
   - 전문가 검수 전이라는 안내는 한 번만 넣었어요.
   - 미검증 조합(편인–편재 등)은 규칙으로 쓰지 않아요. 전통적으로 이름 붙은 흐름(식상생재·관인상생·재생관)만 남겼어요.
   - 대운·올해·재회는 다루지 않는다고만 적었어요.
   - 같은 명식(A·C)이면 1~6장이 같고, 고민이 다르면 7장이 달라요.
6. **안전**:
   - 기존 프로젝트 ID, `reportApp.projects.v1`, 입력·편집·보존된 편집본·history·직접 고른 색, JSON 형식을 그대로 읽어요.
   - 생성기 버전이 v2로 올라서, 예전 프로젝트를 열면 현재 본문으로 대조·정규화하고 재검토를 요구해요. 예전 문단에 했던 편집은 "보존된 편집본"으로 옮겨져요.
   - 디자인을 바꾸면 고친 문장은 그대로 두고 검토 완료만 풀어요. 출생 정보나 고민을 바꾸면 기존처럼 막혀요(stale).
   - 새 설정은 모두 스키마로 검사하고, 화면에 넣을 때 이스케이프해요. CSP와 미리보기 격리도 유지했어요.

## 실제 생성 결과 (프로그램이 만든 그대로, 문장 수정 없음)
정적 배포본을 브라우저로 열고 화면 조작만으로 만든 결과예요(`report-web/test/make-samples.mjs`).
- `A_가상사례A_일진로_신비로운밤.pdf`
- `B_가상사례B_일진로_차분한서재.pdf`
- `C_가상사례C_A와같은명식_돈고민_따뜻한종이.pdf` — A와 같은 명식이고 고민만 다름

세 파일 모두 최종본이고, 만드는 동안 외부 요청은 0건이었어요. 이 PDF들은 Node의 PDF 자동 검사(Poppler)로 확인했고, 짧은 쪽은 B 16쪽(명식표 쪽) 하나였어요. 화면으로 직접 보고 문제없음을 확인했어요.

## 시험 결과
- 정적 E2E 50/50 · 로컬 E2E 64/64
- 리포트 생성 110 · 장 생성 49 · 브랜드 41 · 비용·개인정보 17 · KST 86 · 점찍 교차 16
- 새로 넣은 시험:
  - 디자인을 바꿔도 편집 보존(검토만 해제), 팔레트·글꼴 반영
  - 로고: PNG 허용, SVG·2MB 초과 거절, 표지에 들어감
  - 인사말에 넣은 공격 문자열이 글자로만 표시됨
  - 브랜드 프로필: 저장, 새 고객 자동 채움, 기존 프로젝트 안 바뀜, 잘못된 프로필 거절
  - 이전 버전 JSON(bright·v1·옛 문단 편집) 가져오기
  - 디자인 5종 실제 인쇄: 제목 글꼴 포함, 대체 글꼴 없음, 30자 이름 표지, 명식표
  - 모바일 390px: 가로 넘침·잘린 버튼·안쪽 스크롤 없음
  - 새로고침 후 이어서 하기, 디자인 카드 반복 클릭
  - 선택지 6종 분류, 조사 표식 없음, 3·4·7장이 월간 설명을 되풀이하지 않음, 다시 펼칠 곳이 실제 절을 가리킴
- 시험 환경: Linux x64, Chromium 141(Playwright 1.56.1), 브라우저 시간대 America/Los_Angeles

## 미검증 범위
- Windows Edge·Chrome, Mac Chrome·Safari, 실제 휴대폰은 실행하지 않았어요. 모바일은 390px 화면 크기로만 확인했어요.
- 사람이 실제 인쇄 창에서 "PDF로 저장"을 눌러 만든 파일은 확인하지 않았어요(같은 인쇄 문서를 Chromium 인쇄 엔진으로 저장해 확인). 브라우저 버전에는 자동 페이지 나눔 검사가 없어요.
- 실제 HTTPS 호스팅, 명리 전문가 검수(라이브러리 1~5는 초안), 실제 이메일 연결, 구매자 접근·사용 기간·지원 기간 결정은 하지 않았어요.
- 이 환경의 headless Chromium은 한글 다운로드 파일명을 `download`로 보고해요. 그래서 앱이 지정한 이름을 기록하는 방식으로 확인했어요.
